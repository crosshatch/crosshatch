# Configuration

`ChxStage` and `ChxDomain` replace the former `ChxEnv` service.

## Stage

```ts
import * as ChxStage from "@crosshatch/util/ChxStage"
import { Effect } from "effect"

const stage = ChxStage.ChxStage.pipe(Effect.provide(ChxStage.layer))
```

A stage is `dev_${string}`, `staging-${number}`, or `prod`. `ChxStage.layer`
reads `VITE_PUBLIC_CHX_INTERNAL_STAGE` in Vite environments, then
`CHX_INTERNAL_STAGE`. Missing or invalid configuration defaults to `prod`.

## Domain

```ts
import * as ChxDomain from "@crosshatch/util/ChxDomain"
import * as ChxStage from "@crosshatch/util/ChxStage"
import { Effect, Layer } from "effect"

const domain = ChxDomain.ChxDomain.pipe(
  Effect.provide(
    ChxDomain.layer("example.com").pipe(Layer.provide(ChxStage.layer)),
  ),
)
```

The service provides `{ name, url }`. Production leaves the hostname unchanged,
staging prefixes it with the stage, and development appends `.localhost`:

| Stage       | Name                    |
| ----------- | ----------------------- |
| `prod`      | `example.com`           |
| `staging-3` | `staging-3.example.com` |
| `dev_alice` | `example.com.localhost` |

The old `VITE_PUBLIC_ALCHEMY_STAGE` and `ALCHEMY_STAGE` variables and
`ChxEnv.domain`/`ChxEnv.url` builders are no longer used.
