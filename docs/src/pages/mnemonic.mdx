# Mnemonic

`Mnemonic` is the private phrase used by Crosshatch's built-in signer layers.
Treat it as foundational key material: EIP-155 and Solana signing capability can
both be derived from the same mnemonic.

Both EIP-155 and Solana mnemonic signers consume the same `Mnemonic.Mnemonic`
service:

```ts
import { Mnemonic } from "crosshatch"
import { Eip155Signer } from "crosshatch/Eip155"
import { SolanaSigner } from "crosshatch/Solana"
import { Layer } from "effect"

const layerSignersFromMnemonic = Layer.mergeAll(
  Eip155Signer.layerFromMnemonic,
  SolanaSigner.layerFromMnemonic,
).pipe(Layer.provide(Mnemonic.layerFromEnv))
```

## Secure Node Storage

Node.js applications can load a named mnemonic from `MnemonicStore` instead of
keeping the phrase in an environment variable. `ChxNodeServices.layer` stores
the encrypted mnemonic metadata under `~/.config/crosshatch` and keeps the
encryption key in the operating system keychain.

```ts
import { NodeServices } from "@effect/platform-node"
import { MnemonicStore } from "crosshatch"
import * as ChxNodeServices from "crosshatch/ChxNodeServices"
import { Layer } from "effect"

const layerMnemonic = MnemonicStore.layerMnemonicFromName().pipe(
  Layer.provide(ChxNodeServices.layer),
  Layer.provideMerge(NodeServices.layer),
)
```

With no argument, `layerMnemonicFromName` loads the `default` mnemonic. Create
it with:

```sh
pnpm crosshatch mnemonic add
```

Use `pnpm crosshatch mnemonic add work` and
`MnemonicStore.layerMnemonicFromName("work")` for a named mnemonic. The
`MnemonicStore.MnemonicStore` service also exposes `add`, `get`, `list`,
`describe`, `remove`, and `rename` for applications that manage accounts
programmatically.

## From Text

Use `fromText` when you already have the phrase in memory.

The text must be a valid English BIP-39 mnemonic, including a valid checksum. An
arbitrary string with a supported word count is rejected.

```ts
import { Mnemonic } from "crosshatch"

const mnemonic = Mnemonic.fromText(
  "test test test test test test test test test test test junk",
)
```

Use `layerFromText` to provide that phrase as the `Mnemonic` service.

```ts
import { Mnemonic } from "crosshatch"

const layerMnemonicFromText = Mnemonic.layerFromText(
  "test test test test test test test test test test test junk",
)
```

## From Config

Use `fromConfig` and `layerFromConfig` when the phrase comes from an Effect
config source.

```ts
import { Config } from "effect"
import { Mnemonic } from "crosshatch"

const layerMnemonicFromConfig = Mnemonic.layerFromConfig(
  Config.string("BUYER_MNEMONIC"),
)
```

The default environment variable helpers read `MNEMONIC`.

```ts
import { Mnemonic } from "crosshatch"
import { Effect } from "effect"

const program = Effect.gen(function* () {
  return yield* Mnemonic.fromEnv
})

const layerMnemonicFromEnv = Mnemonic.layerFromEnv
```

## Random Mnemonics

`Mnemonic.random` creates a new random mnemonic. `Mnemonic.layerRandom` provides
a fresh random mnemonic as a layer.

```ts
import { Mnemonic } from "crosshatch"
import { Effect } from "effect"

const program = Effect.gen(function* () {
  return yield* Mnemonic.random
})
```

Use random mnemonics for tests or disposable local flows. For Node.js payer
clients, prefer the encrypted `ChxNodeServices` store. Other runtimes can
provide a mnemonic with `layerFromEnv`, `layerFromConfig`, or a custom layer
appropriate to their secret-storage platform.
