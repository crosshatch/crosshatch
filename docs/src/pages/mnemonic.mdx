# Mnemonic

`Mnemonic` is the private phrase used by Crosshatch's built-in signer layers.
Treat it as foundational key material: EIP-155 and Solana signing capability can
both be derived from the same mnemonic.

Both EIP-155 and Solana mnemonic signers consume the same `Mnemonic.Mnemonic`
service:

```ts
import { Mnemonic } from "crosshatch"
import { Eip155Signer } from "crosshatch/Eip155"
import { SolanaSigner } from "crosshatch/Solana"
import { Layer } from "effect"

const SignersLive = Layer.mergeAll(
  Eip155Signer.layerMnemonic,
  SolanaSigner.layerMnemonic,
).pipe(Layer.provide(Mnemonic.layerEnv))
```

## From Text

Use `fromText` when you already have the phrase in memory.

The text must be a valid English BIP-39 mnemonic, including a valid checksum. An
arbitrary string with a supported word count is rejected.

```ts
import { Mnemonic } from "crosshatch"

const mnemonic = Mnemonic.fromText(
  "test test test test test test test test test test test junk",
)
```

Use `layerText` to provide that phrase as the `Mnemonic` service.

```ts
import { Mnemonic } from "crosshatch"

const MnemonicLive = Mnemonic.layerText(
  "test test test test test test test test test test test junk",
)
```

## From Config

Use `fromConfig` and `layerConfig` when the phrase comes from an Effect config
source.

```ts
import { Config } from "effect"
import { Mnemonic } from "crosshatch"

const MnemonicLive = Mnemonic.layerConfig(Config.string("BUYER_MNEMONIC"))
```

The default environment variable helpers read `MNEMONIC`.

```ts
import { Mnemonic } from "crosshatch"
import { Effect } from "effect"

const program = Effect.gen(function* () {
  return yield* Mnemonic.env
})

const MnemonicLive = Mnemonic.layerEnv
```

## Random Mnemonics

`Mnemonic.random` creates a new random mnemonic. `Mnemonic.layerRandom` provides
a fresh random mnemonic as a layer.

```ts
import { Mnemonic } from "crosshatch"
import { Effect } from "effect"

const program = Effect.gen(function* () {
  return yield* Mnemonic.random
})
```

Use random mnemonics for tests or disposable local flows. For real payer
clients, persist the mnemonic securely and provide it with `layerEnv`,
`layerConfig`, or your own layer.

## CLI Mnemonic Store

The CLI can generate or import named mnemonics for use by `payload` and `ramp`
commands. Names default to `default` where optional.

```sh
crosshatch mnemonic add [name] [--description TEXT]
crosshatch mnemonic import [name] [--stdin] [--description TEXT]
crosshatch mnemonic list
crosshatch mnemonic reveal [name] [--yes|-y]
crosshatch mnemonic remove [name] [--yes|-y]
crosshatch mnemonic rename <name> <new-name> [--yes|-y]
```

`add` generates a mnemonic. `import` securely prompts for a valid English BIP-39
mnemonic unless `--stdin` is specified. Both print the name and derived EIP-155
and Solana addresses as JSON. `list` prints stored names, addresses, and
optional dates and descriptions as JSON.

`reveal`, `remove`, and `rename` ask for confirmation unless `--yes` is passed.
`reveal` writes the unencrypted phrase to stdout; handle its output as sensitive
data.

Entries are recorded in `~/.config/crosshatch/crosshatch.json`. The file stores
an encrypted mnemonic envelope and metadata, while the corresponding encryption
key is held in the operating-system keychain. The public host APIs are also
available to Node applications:

```ts
import { HostMnemonic, MnemonicStore } from "crosshatch/Host"
import * as Derivations from "crosshatch/Derivations"
import type { Mnemonic } from "crosshatch"

declare const mnemonic: Mnemonic.Mnemonic

const MnemonicLive = HostMnemonic.layer("default")
const addresses = Derivations.make(mnemonic)
```

`MnemonicStore` exposes `list`, `get`, `getEntry`, `add`, `describe`, `remove`,
and `rename` for managing the same store.

The former `crosshatch profile` commands and the `profiles` configuration key
have been replaced by `crosshatch mnemonic` and `mnemonics`. Existing
profile-based configuration is not compatible with the new schema. Use
`mnemonic add` to generate a phrase or `mnemonic import` to store an existing
one; onramping is now a separate `crosshatch ramp onramp` command.

## Fiat Onramp

Create an onramp session for the EIP-155 address derived from a stored mnemonic:

```sh
crosshatch ramp onramp --amount 10
crosshatch ramp onramp \
  --amount 25 \
  --provider Coinbase \
  --mnemonic personal \
  --chain eip155:8453
```

`--amount` is a required positive integer. `--provider` accepts `ApplePay`,
`Stripe`, or `Coinbase` and defaults to `Coinbase`. The mnemonic name defaults
to `default`, the chain defaults to `eip155:8453`, and the command prints the
resulting onramp URL.

For programmatic use, the provider and request schemas are exported from
`crosshatch/Ramp`, and the convenience Effect is available from its module:

```ts
import { onramp } from "crosshatch/Ramp/onramp"
import type { CaAccountId } from "crosshatch/Ramp"

declare const recipient: typeof CaAccountId.CaAccountId.Type

const session = onramp({
  amount: 10,
  provider: "Coinbase",
  recipient,
})
```

`OnrampPayload`, `OnrampResponse`, `Provider`, and `Providers` are exported from
`crosshatch/Ramp`. The convenience Effect requires a `RampClient` service.
