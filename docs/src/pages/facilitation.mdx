# Facilitation

Settlement and verification are performed through a facilitator service. The
`FacilitatorClient` module exposes `verify({ payload })` and
`settle({ payload })`. Both operations require a `FacilitatorClient` service in
the Effect context.

Use `FacilitatorClient.layerChx` for the public Crosshatch facilitator, or
`FacilitatorClient.layer({ baseUrl })` for another deployment.

## Crosshatch Facilitator

`layerChx` derives the facilitator URL from the current Crosshatch `Stage`. The
default production stage uses `https://facilitator.crosshatch.dev`.

```ts
import { FacilitatorClient } from "crosshatch"
import { Layer } from "effect"
import { FetchHttpClient } from "effect/unstable/http"

const FacilitatorLive = FacilitatorClient.layerChx.pipe(
  Layer.provide(FetchHttpClient.layer),
)
```

Provide an Effect HTTP client such as `FetchHttpClient.layer` when the runtime
does not already supply one.

## Providing a Facilitator

Provide `FacilitatorClient.layer` when your program should use a different
facilitator URL.

```ts
import { FacilitatorClient } from "crosshatch"
import { Effect } from "effect"

const Program = Effect.gen(function* () {
  // Your merchant routes or settlement effects live here.
})

Program.pipe(
  Effect.provide(
    FacilitatorClient.layer({
      baseUrl: "https://facilitator.example.com",
    }),
  ),
)
```

Any `FacilitatorClient.verify({ payload })` or
`FacilitatorClient.settle({ payload })` call inside the provided scope uses this
facilitator.

## Merchant Settlement

Most merchant servers provide the facilitator client at the application layer so
every paid route settles against the same service.

```ts
import { FacilitatorClient, Payload } from "crosshatch"
import { Effect } from "effect"

const route = Effect.gen(function* () {
  const payload = yield* Payload.pipe(Effect.flatMap(Effect.fromNullishOr))
  const settlement = yield* FacilitatorClient.settle({ payload })
  // ...
}).pipe(
  // [!code focus:start]
  Effect.provide(
    FacilitatorClient.layer({
      baseUrl: "https://facilitator.example.com",
    }),
  ),
  // [!code focus:end]
)
```

## When to Override

Use a custom facilitator when you operate your own settlement service, route
traffic through an environment-specific deployment, or need to test settlement
against a local facilitator.

```ts
FacilitatorClient.layer({
  baseUrl: "http://127.0.0.1:4647",
})
```

The service must implement the `FacilitatorApi` exported from `crosshatch`,
including `POST /verify`, `POST /settle`, and `GET /supported`. Networks
returned by `/supported` are CAIP-2 `ChainId` values; legacy network aliases are
not accepted by the schema.

## Implementing a Facilitator

The Effect HTTP API definition is exported directly from the package root:

```ts
import { FacilitatorApi, FacilitatorApiGroup } from "crosshatch"
```

Use `FacilitatorApi` when implementing or mounting a compatible facilitator
server.

## Development Facilitator

Run a local stub facilitator with the Crosshatch CLI:

```sh
crosshatch dev
```

It listens on `127.0.0.1:4647` by default. The host and port are configurable:

```sh
crosshatch dev --host 0.0.0.0 --port 8787
```

The server exposes `/verify`, `/settle`, `/supported`, `/health`, and
`/openapi.json`. Connect with an explicit client layer:

```ts
FacilitatorClient.layer({
  baseUrl: "http://127.0.0.1:4647",
})
```

The development facilitator always verifies successfully and returns a
placeholder settlement transaction. It does not perform cryptographic
verification or broadcast transactions and must not be used in production.
